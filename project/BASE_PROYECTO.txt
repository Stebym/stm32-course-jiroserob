BASE DEL PROYECTO: CONEXIONES + ENCENDIDO DE PANTALLA + BUZZER + BIENVENIDA
=============================================================================
Este documento reune SOLO lo que ya esta cableado y probado en hardware real
(conexiones, pantalla, buzzer, imagen de bienvenida). NO incluye nada de la
seleccion de jugadores, seleccion de modo, ni la logica de ningun juego --
eso se va a reprogramar desde cero por separado.

=============================================================================
1. CONEXIONES (todos los pines usados hoy)
=============================================================================

-----------------------------------------------------------------------
1.1 Pantalla ILI9341 (SPI1, solo escritura -- sin MISO)
-----------------------------------------------------------------------
  VCC   -->  3V3                    [cable ROJO]
  GND   -->  GND                    [cable NEGRO]
  SCK   -->  STM32 PA5 (D13)        [cable AMARILLO]
  MOSI  -->  STM32 PA7 (D11)        [cable AZUL]
  CS    -->  STM32 PB6 (D10)        [cable VERDE]
  DC    -->  STM32 PC7 (D9)         [cable BLANCO]
  RST   -->  STM32 PA9 (D8)         [cable MORADO/VIOLETA]
  LED (retroiluminacion, si el modulo la trae aparte) --> 3V3 directo,
      sin pasar por ningun GPIO (siempre encendida) [cable ROJO]

  IMPORTANTE: VCC a 3V3, NO a 5V. Las 5 señales de datos/control salen
  directo de pines GPIO del STM32 a 3.3V, sin conversor de nivel logico.
  Si el modulo no trae su propio regulador+level-shifter para 5V, meterle
  5V puede danar el chip controlador o causar imagen con basura.

  El pin SDO/MISO del modulo (si lo trae) NO se conecta -- el driver de
  este proyecto nunca lee la pantalla.

-----------------------------------------------------------------------
1.2 Boton B1 (integrado en la Nucleo)
-----------------------------------------------------------------------
  PC13 -- pull-up externo ya presente en la placa (R30=4k7), no hace
  falta pull-up por software ni cable adicional (viene de fabrica).

-----------------------------------------------------------------------
1.3 Buzzer
-----------------------------------------------------------------------
  Señal --> STM32 PA6
  (tipo activo/pasivo sin confirmar todavia -- ver seccion 3 mas abajo)

-----------------------------------------------------------------------
1.4 Joystick 1
-----------------------------------------------------------------------
  VRy (eje vertical)    -->  STM32 PA1  (ADC1_IN1)
  VRx (eje horizontal)  -->  STM32 PA4  (ADC1_IN4)
  VCC                   -->  3V3
  GND                   -->  GND
  (sin pin SW -- se retiro fisicamente, ya no se cablea)

-----------------------------------------------------------------------
1.5 Joystick 2
-----------------------------------------------------------------------
  VRy2 (eje vertical)    -->  STM32 PC0  (ADC1_IN10)
  VRx2 (eje horizontal)  -->  STM32 PC1  (ADC1_IN11)
  VCC                    -->  3V3  (NO usar 5V -- mismo motivo que 1.1:
                                     el ADC del F411 no tolera mas de 3.3V)
  GND                    -->  GND
  (sin pin SW2 -- se retiro fisicamente, ya no se cablea)

-----------------------------------------------------------------------
1.6 Botones arcade -- Jugador 1 (switch + LED via ULN2003A #1)
-----------------------------------------------------------------------
  Disposicion fisica en la caja (estilo Xbox): ARRIBA=amarillo,
  DERECHA=rojo, ABAJO=verde, IZQUIERDA=azul (es solo cosmetico, la
  logica identifica cada boton por color, no por posicion).

  ROJO      switch --> PB12   LED (control ULN2003A IN) --> PB8
  VERDE     switch --> PA12   LED (control ULN2003A IN) --> PC8
  AZUL      switch --> PC6    LED (control ULN2003A IN) --> PC5
  AMARILLO  switch --> PC9    LED (control ULN2003A IN) --> PA11

  Libre en este tramo: PB9 (por si hace falta un boton mas adelante).

-----------------------------------------------------------------------
1.7 Botones arcade -- Jugador 2 (switch + LED via ULN2003A #2)
-----------------------------------------------------------------------
  ROJO      switch --> PC10   LED (control ULN2003A IN) --> PB5
  VERDE     switch --> PA10   LED (control ULN2003A IN) --> PC4
  AZUL      switch --> PB13   LED (control ULN2003A IN) --> PB14
  AMARILLO  switch --> PB15   LED (control ULN2003A IN) --> PB1

  Libre en este tramo: PB2 (por si hace falta un boton mas adelante).

  Cada switch: pull-up interno del STM32, activo BAJO, sin resistencia
  externa. Cada LED: catodo al OUTx del ULN2003A correspondiente, anodo
  con resistencia de 220 ohm al riel de +5V. GPIO en HIGH = LED prendido
  (el ULN2003A invierte: HIGH en la entrada hace que el OUT correspondiente
  se conecte a GND, completando el circuito del LED).

=============================================================================
2. ENCENDIDO DE PANTALLA
=============================================================================
  - Reloj: HSI interno a 16MHz, sin PLL.
  - SPI1 a 8MHz (prescaler /2), modo solo escritura (no se usa MISO).
  - Secuencia de arranque en main(): HAL_Init() -> SystemClock_Config()
    -> MX_GPIO_Init() -> MX_SPI1_Init() -> ... -> ILI9341_Init().
    ILI9341_Init() manda la secuencia de comandos propia del controlador
    (reset por hardware via RST, salir de sleep, configurar el formato de
    color, encender la pantalla) -- esta parte NO se reprograma, ya esta
    lista y probada.
  - ILI9341_SetPortrait(0 o 1): cambia la orientacion logica entre
    paisaje (320x240) y retrato (240x320) sin recablear nada -- son
    comandos de rotacion del propio controlador.
  - stm32f4xx_hal_conf.h necesita HAL_DMA_MODULE_ENABLED activo aunque el
    proyecto no use DMA (el header de SPI del HAL lo exige para compilar).

=============================================================================
3. BUZZER
=============================================================================
  - Pin: PA6 (queda libre porque el SPI1 de la pantalla no usa MISO).
  - El STM32F411 NO tiene TIM13/TIM14 (esos timers con salida PWM directa
    en PA6 solo existen en la familia F413/F423). El unico timer con canal
    disponible en PA6 seria TIM3_CH1, pero ese ya esta ocupado como
    disparador del ADC del joystick cada 20ms.
  - Por eso el tono NO se genera con PWM de hardware: se alterna el pin
    PA6 por software desde la interrupcion de TIM4 (libre), ver
    MX_TIM4_Buzzer_Init() en main.c. TIM4 corre a una base de tiempo de
    1MHz (BUZZER_TIM_TICK_HZ) y su periodo (ARR) se recalcula segun la
    frecuencia de nota deseada para lograr distintos tonos.
  - PA6 sigue siendo un GPIO de salida normal (push-pull), no una salida
    de timer.
  - Tipo de buzzer (activo vs pasivo) sin confirmar todavia en hardware
    real -- ver [[project_prueba_sonido]] para la prueba dual DC+PWM
    pendiente de correr.

=============================================================================
4. IMAGEN DE BIENVENIDA (splash)
=============================================================================
  - Fuente: imagen.png generada por IA ("NEON RIFF"), originalmente
    1024x768, recortada y redimensionada a 320x240 (resolucion nativa de
    la pantalla en paisaje).
  - Convertida a un arreglo de bytes en formato RGB565 big-endian (2
    bytes por pixel), guardado en Inc/splash_bg.h como
    `static const uint8_t splash_bg[153600]` (320*240*2 = 153600 bytes).
  - Se dibuja con una sola llamada:
      ILI9341_DrawImage(0, 0, LCD_W, LCD_H, splash_bg);
    que manda el bloque completo por SPI de una vez (mismo mecanismo que
    cualquier otro bloque de pixeles, solo que aca los datos ya vienen
    pre-convertidos en vez de calcularse en tiempo real).
  - Cualquier imagen nueva se debe convertir al mismo formato (RGB565 big
    endian, tamano exacto de la pantalla en la orientacion que se vaya a
    usar) antes de generar un header equivalente a splash_bg.h.

5. QUE QUEREMOS HACER EN EL PROYECTO
=============================================================================
  El proyecto se llama "Beat Clash": una consola de juego tipo arcade sobre
  Nucleo-F411RE + pantalla ILI9341, para 2 jugadores cara a cara (cada uno
  ve su mitad de la pantalla invertida 180 grados respecto al otro, como si
  estuvieran sentados uno frente al otro en la misma mesa).

  Todo el hardware de la seccion 1 ya esta cableado y probado (pantalla,
  buzzer, 2 joysticks, 8 botones arcade con sus LED). Lo que se va a
  reprogramar desde cero es TODA la logica de pantalla/juego que iba
  arriba de eso -- seleccion de jugadores, seleccion de modo, y los modos
  de juego en si.

  El foco principal ahora es el modo Guitar Hero (notas cayendo, se golpean
  con los botones/carril correspondiente) -- es el modo mas ambicioso y el
  que se va a construir con mas cuidado, paso a paso. Los otros 2 modos que
  ya se habian hecho antes (Simon Clasico con botones, Simon con joystick)
  quedan como referencia de lo que ya funciono, pero no como el objetivo
  inmediato.

  Forma de trabajar: el usuario va a programar el proyecto por su cuenta,
  paso a paso, mientras que el asistente (Claude) queda disponible para
  dudas, revision de codigo, y para ir agregando funcionalidad puntual bajo
  pedido explicito -- sin adelantarse a escribir modos de juego completos
  por su cuenta.

  |   |                          controlador, primitivas: FillRect, DrawLine,

  |   |-- stm32f4xx_it.c     <- rutinas de interrupcion (ISR): SysTick, ADC,
  |   |                          TIM4 (buzzer), fallas del nucleo.
  |   |-- syscalls.c / sysmem.c / system_stm32f4xx.c  <- generados por
  |   |                          CubeIDE, no se editan.
  |-- Inc/
  |   |-- board_pins.h       <- TODOS los #define de pines (seccion 1 de
  |   |                          este documento sale de aca).
  |   |-- game_state.h       <- constantes de pantalla (LCD_W/H) y los tipos
  |   |                          de datos del estado del juego (notas,
  |   |                          jugadores, puntajes) -- hoy tiene structs
  |   |                          pensados para el Guitar Hero viejo, hay que
  |   |                          revisar cuales siguen sirviendo.
  |   |-- renderer.h         <- prototipos de todas las funciones de dibujo.
  |   |-- ili9341.h          <- prototipos del driver de pantalla.
  |   |-- splash_bg.h        <- la imagen de bienvenida (seccion 4).
  |   |-- imagen_test.h      <- otra imagen de prueba, mas chica, usada en
  |   |                          pruebas anteriores del driver.
  |   |-- stm32f4xx_hal_conf.h / stm32f4xx_it.h  <- configuracion del HAL,
  |   |                          generados/ajustados para este proyecto.

  |-- Startup/                <- arranque assembly + vector de interrupciones
